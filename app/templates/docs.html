QRWaver Documentation

Quickstart, authentication, API reference, examples, and environment tips.

Overview

QRWaver is a Flask-based app that generates trackable QR codes and hosts the images on Cloudflare R2. Saved QRs embed a short link (/s/<slug>) so each scan is counted and shown on your dashboard.

  • Backend: Flask + SQLAlchemy; Auth: JWT in HTTP-only cookies
  • Storage/CDN: Cloudflare R2 (public base via R2_PUBLIC_BASE_URL)
  • Short links: base URL is dynamic in dev (host-based), or uses PUBLIC_BASE_URL in production

Quickstart

1) Authenticate

Email/password login sets a JWT cookie:

curl -i -X POST https://your-domain/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"user@example.com","password":"Passw0rd!"}'
# On success, an HTTP-only JWT cookie is set.

2) Create a trackable URL QR

curl -i -X POST https://your-domain/api/v1/qr/create \
  -H "Content-Type: application/json" \
  -b "cookie-from-login" \
  -d '{
    "type": "url",
    "data": "https://example.com",
    "settings": {"format": "svg", "size": 512}
  }'

3) List your QRs

curl -s -X GET https://your-domain/api/v1/qr -b "cookie-from-login"

4) Simulate a scan

Open the returned short_url (e.g., https://your-domain/s/<slug>). For URL QRs, you'll get a 302 redirect to your target, and the scan counter increases.

Authentication details

  • JWT is set in an HTTP-only cookie; for browser fetch, use credentials: "include".
  • CORS is enabled with credentials; ensure your frontend and API share the proper domain settings.
  • Google login endpoints are available for OAuth/One‑Tap flows.
const res = await fetch("/api/v1/qr", { credentials: "include" });
const json = await res.json();

Rate limits

  • POST /api/v1/qr/preview: default 120 requests/min per IP.
  • POST /api/generate (legacy preview): default 60 requests/min per IP.

API reference

Public

  • GET /ping → { success, status }
  • GET /version → { success, version, build }
  • GET /s/<slug>: records a scan; 302 to the target for URL QRs; renders a minimal page for non‑URL.

Preview (no auth)

  • POST /api/v1/qr/preview: body { type, data, settings } → data‑URI SVG
  • POST /api/generate (legacy): similar interface; returns data‑URI in chosen format.

v1 QR API (auth)

  • POST /api/v1/qr/create → persist QR; returns image URL and short_url
  • GET /api/v1/qr → list QRs with scan_count
  • GET /api/v1/qr/<id>/stats → totals, daily series, simple breakdowns
  • DELETE /api/v1/qr/<id> → remove QR (DB only)

Campaign tagging (UTM parameters)

When you create a QR, you can optionally attach UTM parameters so scans are attributed to a channel and campaign. These values are stored with the QR, logged on every scan, and for URL QRs they are forwarded to the destination URL (without overwriting existing UTMs).

utm_source is a required UTM parameter that identifies the origin of web traffic, such as the website, platform, or publication that a visitor came from. It is used to track and analyze marketing campaign performance, with examples including utm_source=google or utm_source=facebook. This parameter is crucial for understanding where your traffic originates from to inform marketing decisions.

utm_medium is a UTM parameter used to identify the marketing channel or type of link, such as email, cpc, social, or display, that brought traffic to a website. It is a required parameter, along with utm_source, and helps analytics tools categorize traffic to measure campaign effectiveness and optimize marketing efforts.

utm_campaign is a URL parameter used to identify the specific marketing campaign a link belongs to, helping marketers track performance in analytics tools like Google Analytics. It groups related links under a single campaign name, allowing for analysis of how different channels contribute to a campaign's goals, such as a "spring sale" or "product-demo".

utm_term is a specific UTM parameter used to identify the keyword or search term that a user clicked on in a paid search ad. It helps marketers track which specific keywords are driving traffic and conversions, providing more granular data for performance analysis in web analytics tools like Google Analytics. While most commonly used for paid search, it can also be used to identify other targeting details like a topic or audience.

utm_content is a UTM parameter used to identify what specific content or creative was used in a campaign to drive traffic to a website, such as a unique ad, email, or link. It helps differentiate between multiple similar links pointing to the same URL, making it useful for A/B testing and comparing the performance of different versions of content. For example, you might use utm_content=logolink for one version of an ad and utm_content=slogan1 for another, or utm_content=header_link and utm_content=footer_link for two different links in the same email.

Notes: We only allow setting UTMs at creation time. If a short link is opened without UTMs, your stored defaults are used in analytics and forwarded to the final URL (URL QRs only). If the destination URL already has UTMs, we don’t overwrite them.

Error handling

  • Standard JSON: { success: false, error: string, code? }
  • /s/<slug> can return 404 if the slug was created in a different environment.

Environment variables

  • PUBLIC_BASE_URL: base for short links in production.
  • R2_PUBLIC_BASE_URL: public CDN base for R2‑hosted files.
  • Cloudflare R2 credentials; Google OAuth client id/secret; JWT and Flask config values.

Limits & roadmap

  • Current free plan limit example: up to 5 saved QRs per user (enforced in v1 create endpoint).
  • Planned: richer theming, better landing pages for non‑URL QRs, optional asset cleanup on delete.
